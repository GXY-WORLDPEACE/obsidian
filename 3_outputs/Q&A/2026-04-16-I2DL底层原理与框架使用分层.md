# I2DL 内容分层：底层原理 vs 框架使用

## TL;DR

- **NumPy 层**：从零手写，理解每行代码背后的数学
- **PyTorch 层**：掌握工业界标准工具，做真实项目
- **Lecture 层**：理论框架，理解"为什么"
- 课程路径：**先底层再框架**，先理解再应用

## 为什么先底层再框架？

```
┌─────────────────────────────────────────────────────────────────┐
│                                                                 │
│  底层手写的意义：                                                 │
│                                                                 │
│  你能回答这些问题吗？                                             │
│                                                                 │
│  "为什么 ReLU 比 Sigmoid 训练更快？"                             │
│  "反向传播的梯度是从哪来的？"                                     │
│  "卷积层的参数量怎么算？"                                        │
│                                                                 │
│  如果只会 PyTorch 调用，你可能答不上来。                          │
│  但如果手写过一遍，你就真正理解了。                               │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  框架使用的意义：                                                 │
│                                                                 │
│  工业界不让你从零手写，因为他们已经优化好了。                      │
│  你需要知道：                                                    │
│                                                                 │
│  "什么场景用什么工具"                                            │
│  "如何高效调参"                                                  │
│  "如何做完整项目"                                                │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

---

## 一句话总结

| 层次       | 工具          | 目的         |
| -------- | ----------- | ---------- |
| **底层手写** | NumPy / 自己写 | 理解原理，不当调参侠 |
| **框架使用** | PyTorch     | 工业能力，做真实项目 |
| **理论框架** | Lecture     | 理解为什么      |

**学习顺序**：先底层理解 → 再框架应用 → 理论升华
