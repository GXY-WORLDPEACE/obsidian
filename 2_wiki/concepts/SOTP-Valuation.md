# SOTP (Sum of The Parts) 估值法

## 概述

SOTP（分步加总法）将公司拆分为不同业务分部，分别估值后加总。适用于业务多元化、周期阶段不同的公司。

## 核心公式

```
公司整体估值 = Σ(各业务分部估值)

各业务分部估值 = 分部利润 × 适用乘数

示例（美光）：
  AI/HBM业务 → 20-25倍P/E
  传统业务   → 2.5倍P/B
  ─────────────────────
  整体估值   = 加总
```

## 为什么用SOTP？

| 场景 | 传统估值问题 | SOTP优势 |
|------|-------------|----------|
| 多元化业务 | 平均乘数失真 | 分部精准定价 |
| 周期股转型 | P/B低估成长 | P/E捕捉转型 |
| 业务分化 | 混合估值不准 | 业务拆分清晰 |

## 美光SOTP案例

```
云端/数据中心业务（AI/HBM驱动）
  → 营业利润率 66%
  → 给予 20-25倍P/E
  → 享受AI算力基础设施溢价

移动/客户端业务（传统周期）
  → 营业利润率 76%（HBM挤出效应）
  → 给予更高PS但低于AI业务
  → 仍保留周期品框架
```

## SOTP vs 传统估值

| 方法 | 适用场景 | 局限 |
|------|---------|------|
| P/E | 单一业务、稳定盈利 | 周期股失真 |
| P/B | 资产重、周期品 | 忽略成长性 |
| SOTP | 多元化、转型期、业务分化 | 需要合理拆分 |

## 关键假设

SOTP估值依赖各分部的：
1. 利润拆分准确性
2. 乘数选择合理性
3. 协同效应折算
